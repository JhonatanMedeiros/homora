# ADR 0031: Evaluation of evidence-based assistance

**Status:** Proposed (design and scenarios only).

**Date:** 2026-11-25

## Context

[Issue #354](https://github.com/JhonatanMedeiros/homora/issues/354) asks for a repeatable synthetic evaluation usable by incident investigation (#346) and external-agent validation (#351). Evidence and integrated-provider boundaries are proposed in [ADR 0029](0029-evidence-contract.md) and [ADR 0030](0030-ai-assistance-boundary.md). There is no implemented harness or claim of model validation in this decision.

## Decision

Represent each case as a versioned, portable synthetic fixture with a fixed UTC evaluation time, input request, evidence items and coverage, expected supported facts, required gaps, allowed qualified hypotheses, forbidden assertions and required citation IDs. The table below is the normative seed set; IDs are synthetic and local to each row. Consumers must expand its shorthand into ADR 0029 bundles and expected assertions without adding facts. `F` denotes a fact, `U` a gap; a citation to a gap supports only the stated gap, not a missing event. Facts are about recorded observations, not causality. `now` is `2026-01-01T12:00:00Z`; all times below are UTC. Every case has complete source coverage unless a gap says otherwise. Monitor names A and B are synthetic, never real environment data.

For E10 the fixture has no dependency link: no causal hypothesis may assert one. E04 is deliberately sequential observations, not a logical contradiction; an implementation must also test truly conflicting sources at the same timestamp with origin preserved and disagreement unresolved. Add this as E13: request current A; F1 says A succeeded at 11:59 and F2 from a different source says A failed at 11:59, with no precedence information. Report the conflict [F1, F2]; do not pick a winner or invent a cause.

### Rubric and release gate

Assess atomic factual and inferential claims, not just paragraphs. For every claim verify its label, that all referenced IDs exist and are visible, and that the cited items actually support its subject, time and specificity. An unknown cites a coverage assessment when one exists; a request for clarification need not invent a citation. Hypotheses cite supporting facts and explicitly state uncertainty; a citation does not establish causality. Evaluate forbidden assertions and expected gaps independently. A deterministic validator can check shape, IDs and required coverage; a human reviewer must judge semantic support, invented causes, appropriate abstention and adversarial behavior. Record reviewer, fixture version, model/provider and prompt version, outputs in an isolated synthetic test environment, and disagreements; do not use production data. Resolve disagreements before scoring.

For the fixed suite, approval requires: 100% of applicable claims cite valid supporting evidence; 100% correct fact/hypothesis/unknown labels; zero invented causes or other forbidden assertions; all required facts and gaps present; and correct abstention or clarification in every case that requires it. A model response without enough evidence must not assert a conclusion, but can still report supported facts. These are finite-suite gates, not guarantees of safety, privacy or real-world accuracy. Changes to the suite or grading require versioning and renewed review, not silent relaxation.

For integrated-provider performance, run at least 20 independent requests against the approved synthetic fixture set under a documented representative configuration and load, with no retries; report all latencies, failures and timeouts. Use nearest-rank p95, counting a timeout as a failure and reporting it separately. The acceptance target is p95 < 20 seconds and zero timeouts in the run; a stricter feature budget wins. Record per-request estimated/reserved and actual reported cost and require each within its approved limit and the run within the daily ceiling. If actual cost is unavailable, the cost gate is unverified, not passed. External MCP agent evaluations record their own end-to-end latency and costs when measurable; the integrated adapter's 20-second budget does not automatically apply to an agent controlled by another client. Define any MCP latency target in #351.

Store fixtures and grader expectations as versioned files when the harness is implemented, with deterministic IDs, fixed clocks, no personal data and no network dependency for deterministic tests. A real-model run is separately identified, non-deterministic and only performed with an authorized provider and synthetic data. If a provider is unavailable, record that gate as unverified. #346 and #351 may use different interfaces but must preserve the same expected evidence semantics.

## Alternatives

Checking only that a citation exists allows irrelevant citations to mask invented claims. Evaluating only live infrastructure risks private data and makes results difficult to reproduce. A model-only judge without human review cannot independently establish semantic support. Passing a synthetic suite cannot substitute for real-user evaluation.

## Consequences

These scenarios are an evaluation specification, not an executable harness or a passed test. Source-specific fixture schemas, graders, performance configuration and authorized live-model runs remain future work. Organization scenarios in #351 will additionally need proposal, ambiguity, scope and review tests beyond this evidence-focused set.
